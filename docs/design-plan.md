# 설계 계획 (리포 안 기록)

> 원래 설계도는 리포 밖 문서다. 이 파일은 리포 안에서 이어 쓰는 단계별 설계 기록이며, 7단계부터 적는다.

---

## 7단계 혼합 출제 (지문 1개 + 레벨별 여러 유형 + 단어)

- 작성: 2026-09-29 · 코드 기준 조사 (DB 는 읽기만)
- **결론: 지금 저장 구조(exams + exam_questions.question_data snapshot) 안에서 만들 수 있다. DB 구조 변경(migration) 없음.**

### 1. 지금 시험이 저장되는 방식

| 항목 | 문제 시험 (`/create/problem` → `/tests/[id]`) | 단어 시험 (`/create/word`) |
|---|---|---|
| 시험 카드 | `POST /api/exams` → `exams` 한 행, `exam_type: 'problem'` | `POST /api/vocabulary/word-test` → `exams` 한 행, `exam_type: 'word'` |
| 문항 | 시험 화면에서 한 개씩 `POST /api/exam-questions` → `exam_questions` 행 (`question_data` JSON, `sort_order`, `points`) | 같은 요청 안에서 `exam_questions` 여러 행을 한 번에. 실패하면 시험 카드도 지운다 |
| 문항 모양 (snapshot) | 문제은행: `buildBankExamQuestionData` (`source: 'question_bank'`, `source_question_id` = questions.id) · 외부지문: `buildExternalExamQuestionData` (`source: 'external_passage'`, qid 있으면 `source_question_id`, 항상 `source_kind`·`source_index`) | `type: 'word'`, `direction`, `question`(제시어), `answer`, `accepted_answers`, `source: 'vocabulary_bank'`, `source_vocabulary_entry_id` |
| 시험 종류 판단 | `lib/examType.ts`: 저장값이 있으면 그 값, 없으면 추론 (문항 전부 `word` → 단어, 그 밖 → 문제) | 같음 |
| 인쇄 | `/tests/[id]/print`: 문항이 **전부** `word` 이면 단어시험 전용 인쇄(`WordTestPrint`), 아니면 일반 인쇄. 둘 다 학생용(정답 없음) / 교사용 / 답안지만 (`lib/printView.ts`) + 쪽마다 저작권 문구 | 같은 화면 |
| 채점·성적 | 채점(`exam_results`)은 점수 입력 방식이라 문항 종류와 무관. 오답 분석(`/wrong-answers`)은 `question_data.type` 별로 묶어 정답률을 낸다 | 같음 (`word` 가 한 유형으로 묶임) |

### 2. 혼합 시험을 지금 구조에 저장할 수 있나

**a) exam_type** — 새 값('mixed')을 만들지 않는다. 저장할 때 `inferExamType(문항)` 으로 정한다:
지문 문항이 하나라도 있으면 `'problem'`, (지문 문항 0개로) 단어만 있으면 `'word'`. 저장값과 추론값이 항상 같으므로 추론 방식과 충돌하지 않는다.
혼합인지는 "문항에 `word` 와 다른 유형이 섞여 있다"로 알 수 있다 (따로 저장하지 않음). 시험지 보관함에는 '문제 시험'으로 보인다.

**b) 인쇄·채점·성적분석** —
- 인쇄: 혼합 시험은 문항이 전부 `word` 가 아니므로 **일반 인쇄**로 간다. 일반 인쇄는 지문이 같은 문항끼리 묶고, 지문이 없는 단어 문항은 뒤에 따로 모인다. 단어 문항은 보기가 없어 "짧은 답 쓰기 칸"으로 그려진다 → 제시어 옆에 "(뜻을 쓰시오)" / "(영어로 쓰시오)" 안내만 더한다 (`type === 'word'` 일 때만 → 기존 시험은 영향 없음).
- 학생용에는 정답·해설이 그려지지 않는다 (기존 규칙 그대로, 문항 종류와 무관). 교사용·답안지만은 `answer` 를 쓴다.
- 채점(점수 입력): 영향 없음. 오답 분석: 유형별로 묶을 때 `word` 가 '단어' 한 유형으로 나온다 (이름표만 추가).
- 시험 상세 화면(`/tests/[id]`)은 이미 `word` 문항을 "방향 · 제시어 → 정답"으로 보여준다.

**c) qid 없는 외부지문 (14개, 350문항)** — DB 를 고치지 않는다. 문항을 뽑을 때 임시 키 `ext:<지문 id>:<questions|essays>:<위치>` 로 구분하고,
시험 snapshot 에는 기존 방식대로 `source_kind`·`source_index` 를 남기며 **`source_legacy_key`** (같은 값)를 더한다. `source_question_id`(=qid)는 **지어내지 않는다** (나중에 qid 를 채워도 헷갈리지 않게).
qid 가 있는 문항은 지금처럼 `source_question_id` 에 qid 를 넣는다.

**d) 난이도 맞추기** —
- 지문 문항: 통합 1~4 눈금 (`lib/passageUnified.ts`). AI 문항은 문항마다 (beginner 1 · intermediate 2 · advanced 3), 외부지문은 지문 단계 (학교형 1 · 일반학원형 2 · 상위학원형 3 · 선행형 4) — 외부지문 한 지문 안 문항은 모두 같은 단계.
- 고른 레벨의 문항을 **먼저**, 모자라면 **가까운 레벨 순서**(같은 거리면 낮은 쪽)로 채운다. 난이도 없는 문항은 맨 뒤. 미리보기에 문항마다 레벨을 보여준다.
- 외부지문 4단계 세트를 고르면, 고른 레벨의 단계 지문을 쓴다 (그 단계가 없으면 가장 가까운 단계).
- 단어: 단어은행 학년 × 레벨 범위표(`config/vocabularyLevels.ts`) + 방향. **'사용 중'(approved) 단어만** (`generateWordTest` 의 조건 + 저장 API 에서 DB 로 한 번 더 확인).

### 3. 화면 흐름 (`/create/mixed`, 시험 출제 > 혼합 시험) — 구현됨 (2026-09-29)

1. **지문 고르기**: 통합 지문 목록(AI + 외부, 보관 제외)에서 1개. 학년·종류로 좁힐 수 있다.
2. **지문 문항**: 레벨(기초/표준/심화/선행) + 객관식·주관식·문법 개수. 지문을 고르면 유형별로 **있는 문항 수**(고른 레벨 / 전체)를 먼저 보여주고, 요청이 더 많으면 미리 "부족"이라고 알린다.
   - 유형 나누기: AI — 어법 객관식(`grammar`)·서술형 어법고쳐쓰기 → **문법**, 어휘·독해·지문요약 → **객관식**, 그 밖 서술형 → **주관식**. 외부지문 — `mc`·`tf` → **객관식**, `blank`·`order`·`match`·서술형 → **주관식**, 외부지문에는 문법 표시가 없어 **문법 0개**.
   - 지금 DB 기준 (읽기만 확인): AI 문항 574개 = 객관식 315 · 주관식 66 · 문법 193 (45세트 모두 문항 있음). 외부지문 350개 = 객관식 187 · 주관식 163 · 문법 0.
3. **단어 문항**: 개수 + 학년 + 레벨 + 방향(영→한/한→영).
4. **뽑기 → 미리보기**: 뽑힌 문항 목록, 문항별 교체(같은 유형·같은 지문 / 같은 조건 단어)·삭제, 다시 뽑기.
5. **저장** → 인쇄 화면(학생용 기본)으로 이동. 교사용·답안지만은 인쇄 화면의 기존 전환 버튼.

- 부족하면 **있는 만큼만** 넣고 알린다. 다른 지문·다른 레벨 단어로 몰래 채우지 않는다 (지문 문항의 '가까운 레벨 채우기'는 같은 지문 안에서만, 미리보기에 레벨 표시).
- 오래된 결과 무시: 조건(지문·레벨·개수·단어 조건)을 바꾸면 미리보기를 비우고 seq 를 올린다. 늦게 도착한 문항 목록·뽑기 결과는 버린다 (`lib/wordTestDraft.ts` 와 같은 방식, `lib/mixedTestDraft.ts`).
- 저장 API: `POST /api/exams/mixed` — 시험 카드 + 문항을 한 번에, 실패하면 시험 카드를 지운다 (단어시험 저장과 같은 방식).

### 4. 위험

1. **유형 나누기가 근사치**: 외부지문 문항에는 "문법" 표시가 없고, AI 서술형 종류 이름으로 문법을 판단한다. 선생님 기대와 다른 칸에 들어갈 수 있다 → 미리보기에서 교체·삭제로 바로잡는다.
2. **qid 없는 외부지문 문항**: 임시 키(위치 기반)라서, 나중에 그 지문의 문항 순서를 바꾸면 "이미 담은 문항" 판단이 어긋날 수 있다 (시험 snapshot 자체는 바뀌지 않음). 근본 해결은 `backfill-passage-qids` 실행 — 이번에 하지 않음.
3. **시험지 보관함에서 혼합 여부가 따로 보이지 않음**: exam_type 을 늘리지 않았으므로 '문제 시험'으로 보인다. 단어 문항 수가 많은 시험은 오답 분석에서 '단어' 유형으로 묶인다.

### 5. 못 하는 것 (이번 범위 밖)

- 지문 2개 이상 섞기, 유형별 배점 다르게 (한 시험 한 배점, 저장 뒤 시험 상세에서 문항별 배점 수정은 기존 기능으로 가능).
- 외부지문 '문법' 문항 자동 분류 (표시가 없음).
- 혼합 시험 전용 인쇄 모양 (일반 인쇄 + 단어 안내 한 줄).
- exam_type 'mixed' 로 따로 저장·필터 (migration 필요 없이 할 수 있지만 보관함·통계 필터 전부를 바꿔야 해서 보류).
